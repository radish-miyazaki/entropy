## TL;DR

- 出すと要望、バグ報告、提案が押し寄せる。慌てて反応せず、数日待って落ち着かせる。
- 反応に応じてその場で約束すると、次のサイクルを白紙で始められなくなる。要望にはやわらかく「No」と返す。
- 反応は形を決めて初めて動ける仕事になる。本当に大事なら、次のサイクルの Shaping で最優先にする。

## 内容

### 嵐が過ぎるのを待つ

出すと、機能の要望、バグ、提案といった新しい仕事が生まれる。見た目を変えると反発が来やすく、強く反応しすぎる顧客もいる。落ち着いて、反射的に動かない。数日おいて反応が落ち着くのを待ち、なぜその変更をしたのか、誰の役に立つのかを思い出す。

### 借りを作らない

反応に応じて変更を約束すると、次のサイクルに必要な白紙がなくなる。寄せられた反応は生のアイデアとして扱い、やわらかく「No」と返す。「No」と言っても、後でそのアイデアの形を決めることはできる。「Yes」と言うのは借りを作るようなものである。

出したものは 6 週間の賭けだったので、その部分にさらに手を入れるなら新しい賭けが要る。要望もバグも次の Betting table でほかの候補と競わせ、戦略的に大事なことを示させる。

### 反応も形を決める必要がある

反応は形を決めるまで手を付けられる仕事にならない。反応は Shaping の最初の手順である[[Shape Up： Stop Running in Circles and Ship Work that Matters 第3章 Set Boundaries|範囲を決める]]段階に入れる生の材料である。

本当に大事な要望なら、次のサイクルの Shaping で最優先にすればよい。その間、チームは別のものを作り、新しいアイデアはきちんと形を決める。6 週間後、形を決めた案を Betting table に出せば、うまくいく見込みが一番高くなる。
