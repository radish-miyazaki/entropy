## TL;DR

- 言葉のアイデアを、ソフトウェアの解決策の要素に変える段階。いくつも案を試すので速さが要る。
- 画面のつながりは [[breadboarding|breadboard]] で、配置そのものが問題なら [[fat-marker-sketch|fat marker sketch]] で描く。どちらも細部を描き込めない粗さにしてある。
- 出てくるのは仕様ではなく要素で、デザイナに余地を残す。

## 内容

[[appetite|Appetite]] と問題が決まったら、言葉で書かれたアイデアをソフトウェアの要素に置き換える。やり方はいくつもあるので、素早く進める必要がある。

### ちょうどいい速さで進める

速く進めるには条件が 2 つある。1 つ目は部屋にいる人を絞ること。1 人で進めるか、同じ速さで考えられて背景を共有している信頼できる相手と 2 人で進める。2 つ目は描くものの細かさを間違えないこと。ワイヤーフレームを描くと、要らない細部で止まってしまう。

前に進めるくらいには具体的に、細部には引き込まれないようにする。考えるのは、新しいものが今のシステムのどこに入るか、どうやってそこへ行くか、主な部品や操作は何か、そこからどこへ行くか、である。そのために breadboarding と fat marker sketch を使う。

### Breadboarding

電子工学のブレッドボードから借りた考え方である。ブレッドボードには部品と配線が全部あるが、製品の外装はない。表示ランプとつまみを付けると決めることと、筐体の素材や角の丸みを議論することは別の話である。

breadboard では次の 3 つを言葉で描く。

- 場所: 画面、ダイアログ、メニュー
- [[affordance|アフォーダンス]]: ボタンや入力欄など、ユーザが操作できるものと画面の文言
- つなぐ線: どのアフォーダンスからどの場所へ移るか

例は請求書ツールの「自動支払い」である。請求書の画面に「自動支払いをオンにする」を置き、カード情報の入力欄、金融機関のロゴ、送信ボタンのある設定画面へつなぎ、確認画面へ進む。描くと、自動支払いをオンにしたら今の請求書も払われるのか、といった疑問が出てくる。別案として支払いの流れの中に自動支払いを入れると、口座引き落とし（ACH）にも対応していることが分かった。自動支払いを止める手段については、ユーザ名とパスワードでログインする流れを作るのは Appetite に対して大きすぎると判断した。請求する側がすでに持っている顧客の詳細画面から止められるようにした。

### Fat marker sketch

2 次元の配置そのものが問題のときは、breadboard では要点を外す。そのときは fat marker sketch を使う。細部を描き込めないほど太い線で描くスケッチで、最初は紙に太いマーカーで、今は iPad で太いペンを使って描いている。

例は To-Do のグループ分けである。Basecamp の To-Do リストで、利用者が「––– Needs testing –––」のような見出し代わりの項目を作っていたことから生まれた。区切りの上を「どこにも属さない To-Do」、下を「グループに入った To-Do」に分けた。グループごとに追加ボタンを置くとリストの見た目が崩れそうだったので、各項目の横のつまみから開くメニューに追加の操作を移した。スケッチはサイドバーのように中心ではない配置の要素に引きずられることがあるので注意する。手法に名前を付けておくと、早まって細部に入るのを防ぎやすい。

### 出てくるのは要素

この段階の成果は要素である。

- 自動支払い: 既存の「請求書を支払う」画面に「自動支払いに使う」のチェックボックスを置く。請求する側に「自動支払いを止める」を置く
- To-Do のグループ: 最初のグループより上の To-Do は親のリストに属す。グループに入った To-Do はその下に並ぶ。各セクションに追加の操作を置き、見た目がだめならメニューにする
- Dot Grid: 2 か月分の月表示のグリッド、予定は帯ではなく点で示す、点を押すとその予定までスクロールする予定一覧

「月表示のカレンダー」よりずっと狭い。この絞り込みが [[shaping|Shaping]] の狙いである。

### デザイナに余地を残す

具体的なモックは細部まで指示だと受け取られるので、その後の作業を縛る。上の立場の人が出したモックはとくにそうなる。breadboard や fat marker sketch ならデザイナに余地が残る。形を決めた成果は仕様というより「ゲームの範囲とルール」に近く、始まればいろいろな展開がありうる。

### まだ人に渡せる形ではない

この段階の成果は非公開で、壁やノートに描いたものは外の人にはほとんど読めない。進め方は決まったが、大きな未知が残っているかもしれない。次は、決めた Appetite の中でリリースできなくなるような穴がないかを確かめてリスクを減らし、[[shape-up-pitch|Pitch]] に書き起こす。

### ベルトコンベアではない

まだ[[shape-up-bet|賭け]]も約束もしていないので、この段階でやめてもよい。それでも、[[raw-idea|生のアイデア]]を動ける形にしたので、価値は上がっている。時間の割り振りを決めるときに推しやすい選択肢になる。
